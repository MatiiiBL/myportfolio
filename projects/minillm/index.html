Overview

I wrote minillm: an inference engine for Llama-architecture language models in C++20, with no dependencies beyond a test framework and a JSON parser. It loads SmolLM2-135M (30 layers, 576 wide, 9 query heads sharing 3 key-value heads) from its safetensors checkpoint, tokenizes the prompt, runs the forward pass over a preallocated KV cache and samples the continuation. Its 64-token greedy generations match PyTorch's token for token.

An inference engine can be wrong and still write fluent text: pair the RoPE dimensions the wrong way, or assume the usual RoPE base instead of SmolLM2's 100,000, and the model just gets a little worse. So correctness comes first. Every kernel exists twice: a naive scalar reference checked against PyTorch, and an optimized version (NEON, threads, an online softmax) checked against the reference. Weights can be held as f32, bf16 or Q8_0, an 8-bit format with one f16 scale per 32 weights. Q8_0 takes 143 MB: 3.8× smaller than f32 (538 MB), and 1.9× smaller than the bf16 checkpoint (269 MB) that the engine loads by default.

Results

The 64-token greedy generations for each of the oracle's three prompts match PyTorch's id for id, with f32 and with bf16 weights; with Q8_0 weights they match PyTorch running on the same rounded weights. Every hidden state and the final logits are compared with PyTorch's, layer by layer.

Measured error against PyTorch

Floating-point addition is not associative, so a kernel that sums in a different order differs from PyTorch in the last bits. Each tolerance is set from a measurement taken with every tolerance at zero, and all of them live in one file.

How it works

Two implementations of every op

src/ops_ref/ holds naive scalar loops: no SIMD, no threads, no fast-math. They are checked against PyTorch's intermediate values and never optimized, because every tolerance in the repository is measured against them. The engine calls src/ops/, and each kernel there is checked against the reference on random inputs and against PyTorch on real ones. The interfaces between the ten modules are nine frozen headers, so the slow and the fast version of an op have the same signature and share one test.

The cache is the attention kernel's input

The KV cache is allocated once, as [layer][position][kv_head][head_dim] floats, and never resized. The K and V projections write straight into their position and RoPE rotates the keys in place, so a layer's cached prefix is one contiguous [len, 3, 64] block that attention reads without a copy. Causality is a loop bound; there is no mask. Attention runs an online softmax over blocks of 128 keys (the flash-attention recurrence) and handles the three query heads of a group together, so every K and V vector it loads serves three heads.

Q8_0 without giving up exactness

A Q8_0 weight stands for exactly the f32 matrix q × d, so the references apply unchanged. To decode one token, the kernel widens a block's 32 int8 values to float, takes their dot product with the input unscaled, and folds the scale in with one fused multiply-add: d · Σ x·q. For a long prompt, converting per row would cost more with every row, so a panel of weight rows is dequantized once into scratch memory and a register tile runs every input row against it. Both kernels compute each output the same way however the work is split, so results are bitwise identical at every thread count.

Limits

  • One sequence at a time. There is no batching.
  • f32 compute throughout. bf16 and Q8_0 change how weights are stored, not the arithmetic, and the KV cache stays f32: 45 KiB per token, 360 MiB for SmolLM2's full 8,192-token context.
  • Llama-family checkpoints only. The config loader rejects RoPE scaling, attention or MLP biases and activations other than SiLU instead of computing something else.
  • Q8_0 is slow on x86. There the kernels run a portable path meant for correctness: in CI's x86-64 build, Q8_0 decode runs at about half the speed of f32, because SSE2 has no cheap int8-to-float conversion.
  • No committed speed results. The benchmark runs in CI on every push, but its results are not in the repository, so this page quotes none.

The README has no limitations section; these are from the engine's own headers and kernel notes. Source: include/minillm/model.h, include/minillm/config.h, src/ops/q8_0.cpp.
